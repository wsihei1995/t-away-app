# 天水圍人車隊 T-AWAY

## 網頁
- `index.html`：客人外賣前台
- `admin.html`：餐廳、菜單及訂單管理後台
- `supabase-config.js`：瀏覽器用 Supabase Project URL 及 Publishable key（不可放 secret/service role key）

## 雲端版本使用方法
1. 在 Supabase Authentication → Users → Add user 建立後台管理員 Email／密碼。
2. 打開 `admin.html`，用該 Email／密碼按「登入雲端後台」。
3. 第一次登入時，如果餐廳表仍是空白，系統會把示範餐廳及菜單初始化到 Supabase；之後你可直接新增、修改、刪除及上下架資料。
4. 客人前台會讀取 Supabase 的上架餐廳及菜單。
5. 客人訂單會寫入 Supabase；後台可即時看到新訂單，並按「確認接單 → 開始製作 → 出發配送 → 標記已完成」更新狀態。

## 客人訂單狀態即時更新
如果你已經先前執行過舊版 schema，需要再次在 Supabase SQL Editor 執行目前版本的 `supabase-schema.sql`，讓系統建立 `order_tracking` 安全追蹤表。之後客人前台會即時收到後台的接單、製作、配送及完成狀態，不會公開地址或電話資料。

## 餐廳及菜式分類
前台支援飯類、麵食、飲品、小食、甜品等分類。每間餐廳的菜式可以有自己的分類，客人打開餐廳菜單後可以按分類篩選；後台管理員在編輯餐廳時，可以修改餐廳分類，以及逐項修改每款菜式的分類，也可以輸入自訂分類。

如果已經使用舊版資料庫，需要再次執行目前版本的 `supabase-schema.sql`，讓 `menu_items` 增加 `category` 欄位；舊菜式會先按名稱自動分配初始分類，之後可在後台修正。

## 客人送餐資料
付款頁面會提供「記住地址及電話，下次自動填寫」選項。資料只保存在客人目前手機／瀏覽器的 localStorage，不會用作公開訂單追蹤資料；客人可以取消勾選，或按「清除」刪除已記住資料。換手機、換瀏覽器或清除網站資料後，需要重新輸入。

如要讓同一位客人在不同手機登入後仍然同步地址，需要另外加入客人帳戶及受 RLS 保護的 customer profile 表，現版本尚未啟用。

## 示範模式
- 未設定或未使用雲端管理員帳戶時，可在 `admin.html` 輸入示範 PIN：`8888`。
- 示範模式資料只儲存在目前手機／瀏覽器的 localStorage，不會與其他客人或裝置同步。

## 訂單及權限
- 公開前台可以讀取上架餐廳／菜單及建立訂單，但不能讀取其他訂單。
- 只有 Supabase Auth 登入後台的帳戶可以讀取及更新雲端訂單、餐廳及菜單。
- 正式使用前，建議在 Supabase 再收緊 RLS，限制只有指定管理員帳戶可以管理餐廳及訂單。

## 付款功能狀態
前台已加入支付寶、微信支付、轉數快三種付款方式。管理員可以在後台付款設定輸入支付寶／微信 QR Code 圖片網址及 FPS 電話，客人選擇付款方式後會看到相應資料。

現階段是「客人自行付款＋管理員人工確認」流程，未會自動驗證款項，也不是正式付款 API。正式收款需要商戶帳戶、支付服務商及 Supabase Edge Function；個人支付寶不適合直接接入公開網站。

要正式收款，需要：
1. 申請相應支付商戶帳戶。
2. 由安全後端／Supabase Edge Function 保存商戶密鑰，不能直接放在前台 HTML。
3. 接入支付平台 API、付款回調及訂單核對。

## 本地測試
用瀏覽器開啟 `index.html` 看客人前台；用瀏覽器開啟 `admin.html` 管理餐廳資料。正式網址請使用 GitHub Pages 版本，因為部分瀏覽器對 `file://` 的跨來源及模組載入限制較多。
